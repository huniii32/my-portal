# 포털 기능 계획

## 페이지 구성

사이드바는 실제 페이지 이동이다(섹션 앵커 아님). `server.py`가 5개 HTML을
서빙하고, 공통 CSS/JS는 `/assets/portal.css`·`/assets/portal.js`로 공유한다.
`portal.js`는 현재 페이지에 있는 요소만 초기화하므로 없는 ID를 건드리지
않는다. 곰비 비서(assistant.js)는 TODO-LIST 페이지가 아닐 때는 대화창 대신
TODO-LIST 페이지 안내를 보여준다.

- `/` 업무 현황: 히어로 + 오늘 한눈에 보기(앱·할 일·목표 카드) + 앱 상태
- `/apps` 업무 앱: 회사/개인 그룹별 바로가기. 관리형 2종(IPIS·Trading)은 백엔드 상태 확인 후 실행, 외부 링크(Rivals Deck)는 바로 새 탭으로 열기
- `/tasks` 할 일: 공휴일 달력 + 날짜별 할 일 추가·수정·완료·삭제. 우선순위·메모·목표 연결을 갖는다
- `/goals` 목표 관리: `주간 & 일간 목표` 직접 추가·수정·삭제. 수치형(목표 수치 기준)과 체크형(연결된 할 일 완료 기준) + 목표 카드에서 할 일 연결·생성
- `/organize` TODO-LIST: 아침 정리 채팅 + 목표 확정

## 확인한 공백과 구현 결과

- 개인 업무를 날짜별로 남길 수 없었다. `/api/tasks`가 제목·날짜·엄격한 완료 여부를 `tasks.json`에 저장하고, 화면에서 선택 날짜의 할 일을 추가·수정·완료·삭제한다. 할 일은 우선순위·메모를 갖고 `goal_id`로 목표에 연결한다(기간 조회 `from`/`to`, 연결 전용 `PATCH /api/tasks/{id}/link`).
- 목표 진행 수치를 직접 바꿀 수 없었다. 목표 페이지에서 주간·일간 목표를 직접 추가·수정·삭제한다(`POST`/`PATCH`/`DELETE /api/goals/{period}[/{index}]`, id 부여·구 파일 마이그레이션·낙관적 동시성은 내용 기준). 수치형은 목표 수치로, 체크형은 연결된 할 일 완료율로 진행률을 자동 집계한다. 목표 삭제는 할 일을 남기고 연결만 해제한다.
- 앱 상태는 자동 확인만 보였다. 새로고침 버튼은 진행 중 요청을 합치고, 마지막 성공 시간을 보이며 실패 뒤 다시 시도할 수 있다.

## 기존 제한

로컬 단일 사용자 JSON 저장소이며 전체 할 일은 1,000개로 제한한다. 프로세스 하나에서는 잠금으로 보호한다. 여러 worker로 늘리기 전에는 DB나 파일 잠금으로 교체해야 한다. 런타임 파일은 git에서 제외한다.

## 업무 비서 곰비

## 구현 범위

- 고정 오버레이의 곰비는 원본 네 장의 여섯 포즈를 바탕으로 만든 투명 픽셀 아트 `assets/mascot/pixel-{1..6}.png`를 쓴다. 각 PNG는 D 모자·BEARS·야구 소품·포즈를 유지한 채 단색 배경 없이 떠 있으며, 6가지 모습은 새로고침 때 이전 모습과 다르게 고르고 화면과 위젯이 보일 때 60초마다 바꾼다. 곰비 아래에는 기존 대화·이동 정지·숨기기 동작을 연결한 44px 필 버튼이 있다. WebGL과 Three.js 렌더러는 사용하지 않으며, 이미지를 불러오지 못할 때만 CSS 캐릭터로 보인다.
- 곰비는 하단 안전 영역의 제어된 웨이포인트 사이를 실제로 이동한다. 한 requestAnimationFrame 루프가 화면 좌표와 이동 거리·보폭 위상을 갱신하고, 이동 중 원본 스프라이트만 아주 작게 위아래로 흔들고 기울인다. 도착하면 멈추며, 이미지를 좌우 반전하거나 측면으로 돌리지 않는다.
- 이동 경로는 하단 약 60px 범위에 한정하고, 웨이포인트 선택 때 보이는 입력·버튼의 사각형과 시작점부터 목표점까지의 경로를 검사한다. 말풍선이 화면 밖으로 나가지 않는 x 범위도 함께 지킨다. 마우스·키보드 포커스·입력 중·모달·말풍선·숨김 탭·감소된 모션에서 즉시 현재 좌표와 걸음 자세를 유지한 채 RAF를 멈춘다. 창 크기를 바꾸면 현재·목표 좌표만 경계 안으로 보정하며 순간이동하지 않는다. 상단 `내 비서`로 다시 열 수 있고, 패널에서 이동 정지와 숨김을 저장한다.
- `/api/assistant/briefing`은 Asia/Seoul 오늘 날짜 기준으로 오늘 미완료·기한 지난 미완료·현재 주/일 목표만 읽는다. 최대 다섯 항목을 정렬해 돌려주며, 저장소가 손상되면 빈 결과로 가장하지 않고 503을 돌려준다. 이 읽기는 파일을 바꾸지 않는다.
- 비서 패널은 기존 SSE 채팅과 목표 확정 버튼을 그대로 옮겨 쓴다. AI가 없을 때도 결정적 요약과 목록은 보이며, AI에게 넘기는 오늘 할 일은 신뢰할 수 없는 사용자 데이터로 표시한다. 비서는 할 일·목표·앱 실행·거래를 자동 변경하지 않는다.
- 성공한 할 일/목표/채팅 흐름은 명시적 `assistant:notice` 이벤트로만 알린다. OS 알림, 서비스 워커, 백그라운드 작업은 사용하지 않는다.
- 곰비의 proactive 알림은 서울 시간의 아침·점심·마무리 슬롯에서 현재 브리핑의 기한 지난 일·오늘 할 일·목표만으로 결정적으로 만든다. `assistant_preferences.json`의 활성화·시각·자정 넘김 quiet hours를 검증해 저장하고, 브라우저와 데스크톱은 SSE로 변경을 받으며 데스크톱은 본 날짜/슬롯 ID를 XDG 상태 파일에 저장해 재시작 중복을 막는다.
- 비서의 명시적 확인 흐름은 `create_task`, `complete_task`, `reschedule_task`만 허용한다. 서버가 잠금 안에서 원본을 다시 읽고 ID·완료 상태를 확인한 뒤 저장하며, 제안은 거래·주문·삭제·앱 실행·메시지·목표 덮어쓰기를 수행하지 않는다. 확인 결과는 제목·날짜·상태만 최대 20건의 `assistant_activity.jsonl`에 남긴다.

## 오늘의 AI 업무 회고

- `work_digest.py`가 서울 날짜별 Codex·Claude·OpenCode의 사용자 요청, assistant 결과, 세션 제목과 당일 git/HANDOFF 사실을 스트리밍·bounded로 읽는다. tool 출력, 시스템 지시, 첨부 문서, credential/auth 파일과 OpenCode 계정·credential 테이블은 읽지 않는다.
- evidence는 redaction과 중복 제거 뒤에만 LAN Qwen에 전달되며, 모델 실패·응답 오류 때는 근거가 있는 deterministic fallback으로 표시한다. 원문 대화는 저장하지 않고, `work_digest.json`에는 최대 30일의 4개 요약 배열·출처 수·opaque ref만 atomic하게 남긴다.
- 업무 현황의 `오늘의 AI 업무 회고` 카드에서 상태·source count·완료/진행/확인/내일 그룹을 읽고 `지금 정리`로 오늘 digest만 갱신한다. 18:05 타이머(`suhun-work-digest.timer`)와 수동 refresh는 같은 generation lock을 사용하며, digest proactive 알림은 서울 wrap-up 이후 날짜당 한 번만 곰비에 표시한다.

## 의존성과 확인

픽셀 변환은 built-in imagegen의 `style-transfer` 편집으로 만들었다. 원본 포즈를 입력 1, 승인한 첫 픽셀 스프라이트를 입력 2로 두고 “D·BEARS·포즈·야구 소품 유지, 투명 알파 배경, 배경·별·그림자·추가 물체 금지”를 공통 제약으로 썼다. 이전 캐시 페이지를 위해 완성 스프라이트와 `assets/mascot/reference-{1..4}.png` allowlist를 보존하며, `assets/mascot/pixel-{1..6}.png`도 명시 allowlist로 제공한다.

```sh
cd portal
.venv/bin/python -m pytest test/ -q
node --check web/static/portal.js
node --check web/static/assistant.js
node --check web/static/mascot.js
```
